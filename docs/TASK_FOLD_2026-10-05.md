# Auftrag: Fold-/Responsive-Umbau für Lumo Lernen + Lumo Kart

Basis: `claude/lumo-gesamt`

## Bestätigter Befund aus dem aktuellen Code
Die Flutter-App ist bereits grundsätzlich adaptiv geplant. `docs/RESPONSIVE_DEVICE_MATRIX.md` definiert Fensterklassen von Compact bis Large und nennt explizit Fold-Cover, Fold-Innendisplay, Tablet und Hinge/Falz über `MediaQuery.displayFeatures`.

Der kritische Konflikt liegt aktuell beim eingebetteten Kart:
- `scripts/prepare_embedded_games.py` erzeugt die private `LumoGameActivity` mit `screenOrientation="portrait"`.
- Das Kart selbst setzt in Godot beim Start `DisplayServer.SCREEN_SENSOR_LANDSCAPE` und wartet auf eine Landscape-Oberfläche.
- `resizeableActivity="true"` und umfangreiche `configChanges` sind bereits gesetzt.
- Godot nutzt `window/stretch/mode="canvas_items"` und `window/stretch/aspect="expand"`.
- Im Kart wird `content_scale_size = Vector2i(1280, 720)` gesetzt.

Das ist eine echte widersprüchliche Orientierungsvorgabe und muss vor einem Fold-Gerätetest bereinigt werden.

## Ziel
Eine einzige responsive App, keine separaten Builds für Fold/Phone/Tablet:
- Fold-Cover: kompakte Phone-UI
- Fold innen: echtes breites Dashboard, kein hochskaliertes Handy
- Hinge/Falz berücksichtigen
- Wechsel außen -> innen und innen -> außen ohne abgeschnittene UI
- Lumo Kart bleibt Querformat-Spiel, passt aber sauber in Fold-/Tablet-Layouts
- Menü, Rennen, Pause, Zieleinfahrt und Rückkehr aus Hintergrund bleiben stabil

## Paket A – Flutter/Lumo Lernen
1. Zentrale Breakpoints aus `docs/RESPONSIVE_DEVICE_MATRIX.md` tatsächlich verwenden.
2. Neue dunkelblaue Glas-/Hologramm-Screens nicht mit festen Pixelpositionen bauen.
3. Layouts:
   - Compact <=359 dp
   - Phone 360–599 dp
   - Medium 600–839 dp
   - Expanded 840–1199 dp
   - Large >=1200 dp
4. Auf Fold innen Navigation seitlich statt Bottom-Navigation, wo bereits vorgesehen.
5. Ab ca. 1060 dp Insight-/Fortschrittsspalte zulassen.
6. `MediaQuery.displayFeatures` für Hinge/Falz prüfen. Keine primären Buttons über einer trennenden Falz.
7. Alle neuen Screens prüfen: Onboarding, Home, Lernen, Spielewelt, Cards, Belohnungen/Garage, Elternbereich, Einstellungen.
8. Bilder immer mit Safe-Zone und `BoxFit.cover`; Lumo-Fuchs mit `BoxFit.contain`.

## Paket B – Android Host / eingebettetes Godot
1. Die aktuelle Portrait-Sperre in `scripts/prepare_embedded_games.py` nicht beibehalten, wenn sie das Landscape-Kart blockiert.
2. `screenOrientation` und Godot-eigene Sensor-Landscape-Logik aufeinander abstimmen.
3. `resizeableActivity=true` beibehalten.
4. `configChanges` für orientation/screenSize/smallestScreenSize/screenLayout/density prüfen und Regressionstest ergänzen.
5. Keine Activity-Neustarts bei Fold-Wechsel, sofern technisch vermeidbar.
6. Safe-area/insets nach Größenänderung erneut anwenden.

## Paket C – Lumo Kart / Godot
Aktueller Kart-Code setzt 1280x720 als logische Basis und Sensor-Landscape. Das ist als interne Designfläche okay, darf aber nicht bedeuten, dass Touch-UI oder Kamera auf Fold/Tablet falsch skaliert.

Prüfen und umsetzen:
1. `get_window().size_changed` / Displaywechsel abonnieren.
2. Safe-Area und HUD nach jedem Resize neu berechnen.
3. Touch-Controls proportional und mit Mindestgröße platzieren.
4. Keine Steuerung in Hinge-/Cutout-Zonen.
5. Kamera-FOV/Viewport für ultrabreite Innenansichten prüfen; keine Verzerrung.
6. Kart-Menü, Garage, Streckenauswahl, Rennen, Pause, Zielsequenz und Ergebnis jeweils separat testen.
7. Fold öffnen/schließen während:
   - Garage
   - Streckenauswahl
   - Countdown
   - Rennen
   - Sprung/Looping
   - Pause
   - Zieleinfahrt
   - Hintergrund -> zurück
8. Keine Physikwerte an physische Pixel koppeln.
9. 60 FPS nur nach echter Gerätemessung behaupten.

## Testmatrix
Mindestens:
- 320x720 dp
- 360x800 dp
- 412x915 dp
- 600x960 dp
- 768x1024 dp
- 840x720 dp
- 1024x768 dp
- 1280x800 dp

Zusätzlich Fold-Emulator:
- Cover geschlossen
- innen geöffnet
- Live-Wechsel während App und Kart
- Hinge/Falz sichtbar, falls Emulatorprofil dies liefert

## Abnahme
- kein Overflow
- kein abgeschnittener Lumo
- keine unlesbaren Texte
- Buttons >=44 dp
- Navigation immer erreichbar
- Kart bleibt sauber spielbar
- kein ungewollter Neustart
- kein Letterboxing-/Stretch-Fehler
- Screenshots pro Zustand
- Tests PASS/FAIL/SKIP und echte Geräte-/Emulatorangabe dokumentieren

Kein Force-Push, kein Merge nach main und keine Gerätebehauptung ohne echten Lauf.
