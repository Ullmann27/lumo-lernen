# Current-candidate Android integration for English, Quiz and Memory

This change extends the existing Studio2020 acceptance path. It does not merge Main, publish an APK, approve a pending visual receipt or substitute the older Native344 renderer evidence for the new scenes.

## Same-source authority processes

The new parallel activity job checks out the actual candidate Host commit and reads its immutable Native pin from config/godot-source.json. It then checks out that exact Native commit. The recorded Host and Native commits and trees must match before real Dart and Godot execution; tracked source changes fail the job.

English requires its actual Dart producer, the complete fourteen-word catalog, the real rendered activity and17 original PNGs. Quiz requires the complete twenty-question actual-authority pair. Memory retains its independently checked requests/ACKs, real opponent decisions, saved-round reopening and once-only QA award. These desktop adapters are explicitly not a physical Android wallet or Fold7 timing measurement.

The API35/API37 tour waits for all three jobs as well as the existing build and Host compile. The publisher adds the same mandatory successful matrix result. All previous publisher steps, test requirements, job budgets and update checks remain present.

## Actual installed-APK actions

The existing normal21-step tour, learning/Cards surfaces and C4 probe remain first. Each platform then runs Quiz, Memory and English in that order against the same already installed APK. Each new probe independently verifies the actual clean Host/Native sources, APK provenance, embedded PCK and installed APK digest, prior tour and runtime identity. Inputs are real Android taps, swipes and lifecycle actions derived from current observed controls.

Quiz selects and reveals the first real question, advances, selects the second, checks durable state and positive ACKs, pauses/resumes, leaves to Home, returns to Flutter and reopens the same round under a new session. Its read-only answer oracle is explicit QA logic; it does not manufacture a learning result or inject a request.

Memory selects a pair from the actual read-only deck, checks the card-face pixel change, pauses/resumes, makes a nonmatching pair and observes a real Dart opponent state. It then checks Home pause, unchanged unfinished state, Flutter return and a new session token for the same saved round. It does not complete the reward round or write any private application state.

English enters the existing current Schulsachen task and opens its real3D help. It observes real mesh collision projections, a wrong choice, both hints, Home/resume, the correct illustration and return to the same unanswered task. It does not submit an answer, award mastery or change the child's saved learning record.

Android native source checkout now also includes scenes/learning because that actual scene is part of the English source binding. The probes' standard CLI is shared, while each verifies its own activity's authoritative state.

## Local integration checks and remaining gates

The assembled shared reader and three activity probes passed28 English,30 Quiz and25 Memory Python contract cases with no skips. Their source bytes remained unchanged. These are concrete local reader/geometry/state counterexamples; no Android execution is claimed.

The extended workflow parsed as YAML and all70 run/script shell blocks passed bash syntax checking. Existing publisher steps are structurally identical, and the previous job budgets are unchanged. Individual agent reviews and the actual CI runs are recorded separately.

At this checkpoint the new live Android probe sequence has not yet run. The final candidate still needs a current approved Native source/visual receipt, the full Flutter suite, actual Android input/lifecycle/save checks, preserved2017 upgrade and the unchanged release gates. Audio pronunciation, a second-child switch in these three new probes, hardware latency, temperature and measured Fold7 frame rate remain outside this evidence.
