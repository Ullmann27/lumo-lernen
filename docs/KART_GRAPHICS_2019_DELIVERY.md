# Kart graphics 2019 delivery contract

The dedicated workflow is `.github/workflows/lumo-kart-graphics-2019.yml`.
It prepares version **0.13.7+2019** on
`chatgpt/lumo-kart-graphics-apk-20261113`. It does not change or approve the
historical 2018 candidate. The final native pin, explicit `APPROVED[2019]`
policy entry, application version and dated visual receipt are integration
decisions after actual source and image acceptance.

## Preserved acceptance

The workflow retains actual Kotlin/Java host compilation, the complete Flutter
suite and captures, every existing build/preservation and Android-probe contract,
legacy native gameplay, 2014, technical-art, action-stage and Nextgen gates.
It builds and verifies separate signed ARM64 and x86_64 APKs. The complete
original Android tour precedes the same live learning, local speech and Cards
interactions. A separate emulator performs the real 2017-to-2019 in-place update,
offline Kart, restart and simulated Fold checks.

The new update entry point opts into only the exact `(2017, 2019)` pair.
The 2018 entry point keeps its own `(2017, 2018)` opt-in. Both validate the same
strict additive independent-evidence conversion. All old fields, child
namespaces, ownership, rewards and subsequent saved snapshots remain protected.
No probe seeds learning data or substitutes copied preferences for live actions.

Publication requires all four independent jobs to succeed on the same host
commit. The new publisher also compares the PCK hash in **both** ARM64
reinspection reports to the provenance, x86 candidate and actual Android
identities. It preserves existing tags/assets, creates only the new immutable
2019 release, and re-downloads its public APK to verify actual size and SHA-256.
A manual run can build and test but cannot publish.

## Original evidence transfer

The authorized reviewer downloads the three original native archives, checks
their GitHub SHA-256 digests and each PNG against its unchanged image manifest,
opens the actual images, and commits selected original PNGs plus the raw
metadata below. The publisher does **not** try to access another repository's
private artifact ZIPs with the host workflow token. It rehashes the preserved
original files and compares their source and archive identities with the
publicly readable GitHub artifact, run and job records.

The only accepted native workflow is:

| Field | Required value |
| --- | --- |
| Repository | `Ullmann27/lumo-godot` |
| Workflow path | `.github/workflows/lumo-kart-experience.yml` |
| Workflow name | `LUMO Kart world, home and driving graphics` |
| Artifact areas | `home`, `worlds`, `feedback` |
| Artifact names | `lumo-kart-experience-home`, `lumo-kart-experience-worlds`, `lumo-kart-experience-feedback` |
| Required completed jobs | `Actual home scene and interaction`, `Actual worlds scene and interaction`, `Actual feedback scene and interaction` |

All three artifacts must belong to the final native SHA and the same successful
run. A failed overall run cannot approve its successful partial artifacts.
Source trees must agree, source-dirty records must be empty, and the original
logs must contain their required PASS markers without later errors or leaked
resources. Rendered gates additionally require the actual OpenGL renderer header.

## Committed layout

All preserved files live under
`docs/evidence/kart-graphics-2019-reviewed/`. PNGs may be organized into their
four review areas. Metadata uses these exact paths:

- `metadata/run.json` and `metadata/jobs.json`: unmodified GitHub API records
  of the successful final run.
- `metadata/home/`, `metadata/worlds/` and `metadata/feedback/`: each contains
  `artifact.json` from the original GitHub API response plus original
  `source-sha.txt`, `source-tree.txt`, `source-dirty.txt`, `engine.txt` and
  `image-manifest.json` copied from that artifact.
- The home directory additionally contains original `regression.log`,
  `preview-resolution.log`, `cards-header.log`, `home-promenade.log`, `preserved-spatial-menu.log`,
  `preserved-garage.log` and `render.log`.
- The worlds directory additionally contains original `regression.log`,
  `winter-visibility.log`, `render-winter_sprint.log` and `render-crystal_canyon.log`.
- The feedback directory additionally contains original `regression.log`
  and `render.log`.

The source constants `SOURCE_FILES`, `WORKFLOW_FILES` and `REQUIRED_LOGS` in
`scripts/verify_kart_graphics_review.py` define this exact file contract.
Hash original bytes, including newlines; do not reformat JSON or logs.

## Receipt fields

The actual reviewer creates `config/kart-graphics-2019-visual-review.json`
only for the final accepted source. No approved receipt or native policy entry
is generated by these tools.

| Top-level field | Required content |
| --- | --- |
| `schema` | Integer `1` |
| `status` | `approved` only after actual image inspection |
| `versionCode` | Integer `2019` |
| `native_revision` | Final immutable 40-character SHA |
| `native_workflow_run_id` | Actual positive integer run ID |
| `reviewed_by`, `reviewed_at`, `notes` | Reviewer, ISO date with time zone, actual review findings |
| `workflow_metadata_sha256` | Exact mapping of `run.json` and `jobs.json` to their original byte hashes |
| `artifacts` | Three entries defined below |
| `images` | Actually inspected original images defined below |

Each artifact entry contains `area`, `id`, `name`, `sha256` and
`metadata_sha256`. The `sha256` is the original ZIP digest already verified
by the reviewer; public GitHub metadata must still report that same digest.
`metadata_sha256` maps every required filename in its metadata directory
to its exact original SHA-256, including the empty `source-dirty.txt`.

Each image entry contains `path` (repository-relative committed original),
`area`, `artifact_id`, `artifact_entry` (exact original manifest path),
`native_revision`, `sha256`, `dimensions` (`[width, height]`) and
`findings`. Review areas are exactly `home`, `winter_sprint`,
`crystal_canyon` and `feedback`; all four are mandatory. Home needs genuine
portrait and landscape originals. World entries must start with
`images/winter_sprint/` or `images/crystal_canyon/`; home and feedback
entries start with `images/`. Baseline archive images never approve the new
source. Every reviewed PNG is decoded and rehashed against both the dated
receipt and its original manifest.

## Integration and actual release state

Before the first final 2019 PR run, integration must supply the actual native
pin, version, approved policy entry, corresponding current-candidate pin tests,
and complete original evidence/receipt. The 2018 policy entries, workflow,
dedicated update wrapper, publisher and prior evidence remain historical.

Local parser and workflow tests prove rejection behavior, not an APK or an
emulator result. An actual successful complete workflow and verified public
APK download are still required. No desktop result proves physical Fold7 or
Android 17 frame rate, temperature, touch latency or audible voice quality.
